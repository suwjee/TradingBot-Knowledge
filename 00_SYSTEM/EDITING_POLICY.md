# AI editing policy

Read current source and both directional references before changing a trading note. Preserve stable IDs, strict inequalities, exact time/index boundaries, Decimal semantics, tie order, nullable fields, parent/source provenance, direction mapping, and public serialization order. Never invent trading rules or derive correctness from a folder name.

Edit the single owning canonical note and update typed relations. Source notes map code; they do not duplicate a full normative rule. Recompute source hashes after an approved source refresh, and never edit mirrored code in place. Rebuild indexes from frontmatter and validate all relation targets. Record source/reference conflicts explicitly. Do not promote pending-fix OrderAudit, historical evidence, or presentation-only rescues to calculation authority.

The production project is read-only for this Vault build. Future edits to production require a separate task. Preserve .obsidian and any nonempty user notes unless their ownership and migration are explicit.
